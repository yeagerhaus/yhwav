# Full App Audit: Performance, Security, Memory, Dead Code (2026-11-24)

Scope: every tracked TS/TSX file, the `yhwav-audio` Swift module, iOS config, and dependencies. Builds on `docs/audit-2026-07-08.md`; the status of those items is at the bottom.

Baseline at time of audit: `tsc` passes, Biome reports 2 warnings (unused vars in `app/(tabs)/(settings)/appearance.tsx`). There are no automated tests.

Status legend: `[ ]` todo, `[x]` done.

**Implementation notes (2026-11-24 fix pass).** Where the fix differs from the original suggestion:
- Downloads stay in `Documents/`, flagged as excluded from backup, instead of moving to Application Support. This avoids moving every file.
- Lazy Plex URLs: persisted copies store `plex:/path` with no host or token, and are re-resolved on load. In-memory URLs are rebased when the connection changes, so screens are unchanged.
- Native threading: main-queue `runOnQueue(.main)` plus `@MainActor` engine entry points, rather than whole-class actor isolation.
- Huge queues load in appended 500-track windows into both the JS and native queues, so indices never diverge.
- Additional bugs fixed along the way: pausing mid-crossfade froze both decks, "Clear queue" stopped playback, and the background task could notify for episodes past the new cache cap.

## P0: Fix first (data loss, silent playback failure, crashes)

- [x] **Any network failure during auth validation logs the user out**
  `utils/plex-auth.ts` `loadAuthState()`. `getUserInfo()` returns `null` on network errors *and* non-2xx responses, and the caller treats `null` as "token invalid" and calls `logout()`. `loadAuthState()` runs on cold start (`app/_layout.tsx:173`), every time the Account screen mounts (`app/(tabs)/(settings)/account.tsx:40`), and from the background fetch task (`utils/background-fetch-task.ts:84`).
  Trigger: launch in airplane mode, on a flaky connection, or during a plex.tv outage. Auth is wiped, the library is never rehydrated, and downloaded music becomes unreachable. The background task can do this silently.
  Fix: only log out on 401/403; skip validation when offline mode is on; validate in the background *after* hydrating from cache.

- [x] **Crossfades go silent when the screen is locked**
  `modules/yhwav-audio/ios/AudioEnginePlayer.swift:939` (crossfade ramp) and `:1024` (manual-skip fade-in) drive volume with `CADisplayLink`, which does not fire while the app is backgrounded. The ramp is *started* from the progress `Timer` (which does fire), so the incoming deck starts at volume 0. When the outgoing track ends, `handleTrackCompletion` returns early because `crossfadeInProgress` is true (`:1104`). Result: silence, and JS stays on the old track until the app is foregrounded.
  Fix: drive ramps with a `DispatchSourceTimer`, or better, apply the gain ramp on the render thread inside the DSP unit.

- [x] **Downloads are stored by absolute path and backed up to iCloud** (kept in Documents, flagged as excluded from backup)
  `hooks/useMusicDownloadsStore.ts:128,162` and `hooks/usePodcastDownloadsStore.ts:102,115` persist `file:///…/Documents/…` absolute URIs. The iOS app container path can change across reinstalls and updates, after which every download reports "Local file not found". Files in `Documents/` are also included in iCloud backups, which Apple's storage guidelines disallow for re-downloadable content.
  Fix: persist only the filename and resolve against the current directory at read time. Move files to `Library/Application Support` or set `isExcludedFromBackup`.

- [x] **Native module mutates shared state from multiple threads**
  `YhwavAudioModule.swift`: `skip` and `move` read `trackOrder`/`trackMetadata` on the Expo module queue while `add`/`remove`/`reset` mutate them inside `DispatchQueue.main.sync`. `usingPodcastBackend` is written from both threads. `AudioEnginePlayer.play()` runs in a non-isolated `Task {}` and mutates deck, file, and `_isPlaying` state that the main-thread progress timer and completion handlers read. The level tap reads `_isPlaying` from the audio tap thread. Swift collections are not thread-safe, so these are intermittent crash sources.
  Fix: make the module state and `AudioEnginePlayer` `@MainActor` (or confine them to one serial queue) and hop explicitly.

## P1: High impact

**Startup and data layer**
- [x] **Cold start waits on plex.tv before showing anything.** `app/_layout.tsx:173` awaits `loadAuthState()` (1–3 network calls, plus a possible `refreshServers()`) before `rehydrateLibraryStore()` and `initializePlayer()`. The cached library and mini player could appear immediately.
- [x] **The whole library is re-downloaded every 10 minutes while foregrounded.** `app/_layout.tsx:251` plus `utils/library-refresh.ts` re-pull every track page (with stream details), all albums, artists, playlists, and hubs. They then rebuild the indexes, `JSON.stringify` the entire library into MMKV, and trigger a native search-index rebuild. That is heavy on battery, data, and JS-thread time. Fix: compare the section's `updatedAt` first, or fetch deltas with an `updatedAt>=` filter, and refresh much less often.
- [x] **Library cache lives in the default MMKV instance as giant JSON blobs.** `utils/cache.ts:36-45`. Every `Song` carries two full URLs, each with the token and seven identity params. On large libraries this is tens of MB, parsed synchronously on the JS thread at launch, and it shares a memory-mapped file with every small setting. Fix: use a dedicated MMKV instance, SQLite, or a file, and store paths instead of URLs.
- [x] **Stream and artwork URLs are baked at fetch time.** `utils/plex-client.ts:691-694` builds `baseURL + path + token` and persists it. When `refreshConnectionIfNeeded()` switches between local and remote URIs, the cached library, the queue, the stored current song, and download metadata keep pointing at the old host until the next full refresh. Fix: store `part.key`/`thumb` paths and build URLs at play or render time. This also fixes the token-at-rest issue in S1.

**Native audio**
- [x] **The streaming source keeps every compressed packet in RAM for the whole track.** `StreamingAudioSource.swift:250-257` appends packets and never releases them, while also writing the same bytes to disk. A long hi-res FLAC (an hour-long mix, for example) can use several hundred MB and risks a jetsam kill. Fix: read packets back from the persisted file by offset, or drop consumed packets and seek via the file.
- [x] **A failed download can poison the file cache.** `AudioFileCache.swift:260` never checks the HTTP status. A 401/404/503 body is saved as `<trackId>.<ext>` and registered in `cachedFiles`, so later plays of that track skip streaming and fail until the queue is reset. The streaming path also doesn't check the status, or that a resume actually returned 206.
- [x] **The file cache is unbounded within a queue but wiped on every new queue.** `reset()` calls `fileCache.clearAll()` on every `playSound` with a new queue, so replaying an album re-downloads it. Meanwhile a long single queue accumulates files in `tmp/` without limit. Fix: an LRU cap by size, and don't clear on reset.
- [x] **The DSP render callback allocates and locks on the real-time thread.** `YhwavAudioModule.swift:140-330`: it allocates per-callback `[Double]`/`[Float]` buffers for EQ and mono, triggers copy-on-write on the delay arrays (the `let delays = …` copy forces it), and takes an `os_unfair_lock` that main-thread setters contend for. This risks dropouts when EQ or mono is on. Fix: preallocate buffers, use `vDSP_biquadm`, and swap parameters atomically.
- [x] **Synchronous main-thread hops from JS are called from every list row.** `getPlaybackState`/`getActiveTrackIndex`/`getQueue` use `DispatchQueue.main.sync`. `usePlaybackState()` calls `getPlaybackState()` on every progress event and is mounted in every `SongItem` and `SearchSongItem` row (`components/DynamicItem/SongItem.tsx:22`). That is dozens of blocking hops per second while a list is on screen, plus deadlock risk if main ever waits synchronously on JS. Fix: rows should read `isPlaying`/`currentSong` from `useAudioStore`, and native should push state changes as events.

**Playback-state correctness**
- [x] **Toggling shuffle after a partial restore empties the queue.** A partial restore never sets `originalQueue`, so `toggleShuffle()` (`hooks/useAudioStore.ts:985`) builds the queue from `[]`, removes all upcoming native tracks, and persists the empty queue.
- [x] **Restore never finds the current song in the library.** `STORAGE_SONG_KEY` stores a raw ratingKey like `"12345"`. `JSON.parse` turns it into a number, so `songParsed?.id` is undefined (`useAudioStore.ts:489`). It always falls back to the stale stored JSON copy, which carries old URLs and isn't the same object as the library's song.
- [x] **Lock-screen and remote commands are handled twice.** `NowPlayingManager` already calls `performPlayAndSync`/`Pause`/`Seek` natively and then emits `Remote*`, and the JS handler (`useAudioStore.ts:1285-1306`) repeats the action. The JS "suppress spurious RemotePlay after restore" logic (`restoredPausedAt`) cannot work because native has already resumed.

## Security

- [x] **S1. The Plex token is stored in plaintext and copied everywhere.** The default MMKV instance is unencrypted (`lib/storage.ts`), and `plex_auth_state` holds the token. The token is also embedded in every cached track and artwork URL, in the stored current song and queue data, and in download metadata. Fix: keep the token in the Keychain (`expo-secure-store`), create MMKV with an `encryptionKey` held in the Keychain, and stop persisting token-bearing URLs.
- [x] **S2. The token leaks into logs.** Plex request errors embed the full URL including `X-Plex-Token` (`utils/plex-client.ts:386`), and many callers `console.error` them. Release builds ship 169 `console.*` calls in JS/TS and 67 `print` calls in Swift. Fix: redact URLs in errors, strip console calls in release with a Babel plugin, and gate the Swift logs behind `#if DEBUG`.
- [x] **S3. TLS is silently downgraded to HTTP.** `plex-client.ts:317-322,366-372` retries `https://*.plex.direct` as `http://` after a TLS error. Discovery and `testServerConnection` (`utils/plex-discovery.ts:140-154,375-391`) fall back to `http://address:port` even for remote connections. ATS currently blocks non-local HTTP, but on a LAN the token travels in cleartext in the query string. Fix: remove the automatic downgrade and allow HTTP only for private-range addresses with explicit opt-in.
- [x] **S4. Logout and account switches leave the previous account's data behind.** `logout()` only clears auth. The library cache (with token URLs), queue and current song, scrobble queue, UltraBlur cache, and download metadata survive. Because `refreshLibrary` only overwrites non-empty sections, a new account can keep seeing old data. Fix: wipe user-scoped storage on logout and account change.
- [x] **S5. The deep-link scheme is the template default `myapp`** (`app.config.ts`). It collides with other apps, and any app can open routes in this one. Rename it to something unique such as `rite`.
- [x] **S6. Entitlements and plist need cleanup.** `aps-environment` is present but only local notifications are used. `NSLocalNetworkUsageDescription` is missing, so the LAN-server permission prompt shows generic text.
- [x] **S7. The Developer screen and performance debugger ship in release builds** (`app/(tabs)/(settings)/index.tsx:112`). Gate them on `__DEV__`.

## P2: Performance

- [x] **Song rows are heavy.** Besides the per-row `usePlaybackState`, each row has five download-store subscriptions. `isQueued` does an O(queue) scan per row on every store change, so batch downloads re-render whole lists. The memo comparator still only checks `queue.length`.
- [x] **Songs tab sorting is broken and unnecessary.** `app/(tabs)/(library)/songs.tsx:28-62`: Plex already returns `titleSort:asc`. The chunked path mutates one array and keeps calling `setSortedSongs` with the same reference, so React bails out and the list can stay stuck on the first 2,000 items. The timers aren't cleared on unmount, and `localeCompare` with options on every comparison is slow on Hermes. Fix: drop the sort, or use one `Intl.Collator`.
- [x] **Playing from Songs queues the entire library.** (queues over 500 tracks load in appended 500-track windows starting at the selected song) All tracks cross the bridge, and every manual skip re-serializes both ID arrays to MMKV (`saveQueueState` in `skipToNext`/`skipToPrevious`). Fix: persist only when the queue changes, and use a windowed queue.
- [x] **The level meter tap is always on.** `AudioEnginePlayer.swift:1211` taps the main mixer for all playback, including the locked screen, dispatching to main about 43 times a second and emitting a bridge event each time. `MusicVisualizer` starts five `Animated.timing` animations per event. Fix: install the tap only while a listener exists, and use Reanimated shared values.
- [x] **Every progress tick does linear scans.** JS runs `queue.findIndex` twice per 0.5 s tick and Swift runs `trackOrder.firstIndex` several times. Keep a current index instead. This also fixes the duplicate-track-id bugs.
- [x] **Two artwork-color pipelines run per track change.** `react-native-image-colors` downloads the full artwork, and a Plex UltraBlur request runs too. `artworkBgColor` is only a fallback. Pick one, and use ImageColors only offline.
- [x] **Podcast progress causes app-wide churn every 3 s.** `updateResumeAt` rewrites the whole podcast downloads record and replaces the `downloads` object, which re-renders the Home feed and every downloads subscriber. Keep resume positions only in the progress store.
- [x] **The podcast episode cache is unbounded.** Full HTML show notes for every episode of every feed sit in one MMKV key that is rewritten on each refresh. `fetchAllFeeds()` runs sequentially on every launch. Fix: cap episodes per feed, strip or limit descriptions, and parallelize with a concurrency limit.
- [x] **Download bookkeeping is O(n²).** `persistDownloads` stringifies all downloads after each completed track. `snapshotMetadataForSongs` does `Object.values(albumsById).find` per album.
- [x] **`useOfflineFilteredLibrary` is recomputed per screen.** It returns a new object whenever downloads change, even online, which re-renders library screens during downloads. Hoist it into a store or derived selector.
- [x] **Server discovery tests connections serially** with 3 s timeouts each, so login can take tens of seconds. Race the connections with `Promise.any`. The JSON and XML parsing paths duplicate about 130 lines.
- [x] **Search ranking misses matches.** Native search stops at `limit * 2` hits in library order, and the JS fallback stops at 100, so the best prefix matches are often missed. Fix: scan everything and keep the top-k.
- [x] **Retry policy is wrong.** `AbortError` is retryable, so a 120 s library dump can take 8 minutes. POST/PUT/DELETE are retried on timeout, which can duplicate playlists or items. 408 and 429 are never actually retried, despite the comment.
- [x] **Themed styles rebuild on every render.** `useColors()` returns a new object every render when a brand color is set, so `useThemedStyles()` rebuilds styles each render. `GlassDiv` reads the whole appearance store with no selector.

## P2: Correctness (new since July)

- [x] **The token-login fallback corrupts the server list.** `loginWithToken` copies `id`/`uri`/`serverId` onto `recommendedServer`, which is also `servers[0]`. The list ends up with duplicate ids, and the selected server keeps the wrong name and connections.
- [x] **`removeFeed` leaves files behind.** That feed's downloaded episode files and progress entries are orphaned on disk.
- [x] **`reorderQueue` doesn't update `originalQueue`.** A manual reorder is lost when shuffle is toggled off.
- [x] **Now Playing keeps stale data.** It merges into the previous info dictionary, so the old track's artwork lingers. The artwork completion doesn't check that the track is still current.
- [x] **Audio-session edge cases are unhandled.** There's no `mediaServicesWereReset` handling, so the engine stays dead afterward. Pausing on route change doesn't update the Now Playing rate.
- [x] **"Normalization" is not loudness normalization.** It is a per-buffer peak limiter with hard gain steps, which causes pumping. Per-track loudness data is already available, so use it.
- [x] **Background fetch has gaps.** It ignores offline mode, and `expo-background-fetch` is deprecated in favor of `expo-background-task`. A notification tapped from a cold start isn't routed, because `getLastNotificationResponseAsync` is never checked.
- [x] **The "Frosted glass" setting can't be turned off.** Its toggle is commented out in `appearance.tsx`, but the persisted value still applies. This is the source of both Biome warnings.
- [x] **PIN login polling can't be cancelled.** It keeps polling for 5 minutes after the user leaves the screen.

## Suggested order

1. Auth: only log out on 401, and hydrate before validating. Small change, prevents data loss.
2. Background-safe crossfade timer.
3. Relative download paths plus backup exclusion, with a one-time migration of stored URIs.
4. Native threading: `@MainActor` isolation, remove per-row `usePlaybackState`, stop the always-on level tap.
5. Security: Keychain token, redacted logs, no TLS downgrade, full wipe on logout.
6. Library refresh deltas, moving the cache out of default MMKV, building URLs lazily.
7. Streaming memory, file-cache status checks, and an LRU cap.
8. One dead-code PR covering everything in the Vestigial section.
